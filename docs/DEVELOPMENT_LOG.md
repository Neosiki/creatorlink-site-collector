# 개발 일지: Creatorlink 포트폴리오 자료 수집기

날짜: 2026-10-02. 작성: Claude(Anthropic)와 수담님의 협업 기록.

## 1. 요청과 결정
- 요청: `rty0102.creatorlink.net`(류태열 작가 온라인 포트폴리오)의 이미지와 영상을 모두 모아 새 폴더로 저장. 온라인 도록 제작용.
- 처음 추천받은 도구(2순위 website-downloader, 개인 Electron/Puppeteer 프로젝트)는 설치하지 않았습니다. 별 1개짜리 개인 프로젝트이고 실행 파일을 받아 돌려야 해서, 같은 일을 하는 수집기를 직접 만들기로 했습니다.
- 진행 방식 지시: "메뉴 하나씩 완결 형태로 가야 어떤 걸 수집을 끝냈는지 알 수 있다." 이후 메뉴 하나를 끝낼 때마다 보고하고 승인을 받았고, 10번 이후에는 "승인 없이 계속"으로 바뀌었습니다.

## 2. 시행착오 순서
| 단계 | 일어난 일 | 조치 |
|---|---|---|
| 접속 | 클라우드와 PC 셸 모두 403 | 조직 설정의 네트워크 허용 목록에 `rty0102.creatorlink.net`, `storage.googleapis.com` 추가 |
| v1 크롤러(`history/v1_*`) | 한글 경로에서 ASCII 코덱 오류, 170초 제한에 걸려 출력 없음, `pkill -f`가 자기 셸까지 종료 | URL 재인코딩(`q()`), 병렬 BFS(`v2`), 프로세스 종료는 정확한 패턴으로 |
| 백그라운드 실행 | 호출이 끝나면 `nohup`, `setsid` 프로세스도 종료됨 | 메뉴별 포그라운드 실행 + 시간 예산과 캐시로 이어받기 |
| 전체 크롤링 | 사이트 전체를 한 번에 긁으면 어느 메뉴가 끝났는지 알 수 없음 | 메뉴 단위 수집기(`v3_menu_per_menu_collector.py`)로 전환 |
| 1번 메뉴 | 이미지 17장이 `lh3.googleusercontent.com`이라 403 | 허용 도메인 추가(세 번째) |
| 2번 메뉴 | 같은 사진이 크기별(670/800/1920/원본)로 중복 저장, 템플릿 견본 이미지 혼입 | 해시로 묶고 원본 우선, 소유자 폴더만 인정 |
| 1·2번 | 사이트 로고가 작품 1장으로 섞임 | 로고 해시 제외, `00_공통`에 한 번만 저장 |
| 3번 | 캡션이 빌더 기본 문구뿐 | 기본 문구 필터 |
| 4~13번 | 첫 화면만 받는 방식으로 "전부 확보"라고 보고함 | 아래 3번 참조(핵심 오류) |
| 13번 | 3개 목록(26, 30, 44점)이 첫 화면에는 각 12점만 보임 | 목록 API로 전체 수집 |
| 재수집 | 같은 호출이 3분을 넘어 타임아웃, 남은 파일 발생 | 캐시 도입, 남은 파일은 `_이전파일`로 이동 |

## 3. 핵심 오류와 교훈
처음 4~13번 메뉴를 수집한 뒤 "작품 썸네일 N점 전부 확보"라고 보고했습니다. 그러나 N은 첫 화면에 그려진 작품 수였고, 실제 작품은 훨씬 많았습니다. 13번 메뉴 점검에서 페이지에 박힌 JSON의 `view`(12)와 `total`(26, 30, 44)이 다른 것을 발견했고, 사이트 JS를 읽어 '더보기' 요청 주소를 찾았습니다. 이 요청으로 전체를 받아 2~6번, 8~9번, 11~13번을 다시 수집했습니다.

| 메뉴 | 처음 | 정정 후 | 목록 API 작품 수 |
|---|---|---|---|
| 02 구례 대 화엄사 | 62 | 67 | 24 |
| 03 해인사 | 73 | 120 | 73 |
| 04 흑백마애불 암각화 봉정사 통도사 | 216 | 221 | 76 |
| 05 운주사 | 49 | 51 | 26 |
| 06 선암사 | 49 | 125 | 115 |
| 07 법주사 존재시리즈 | 127 | 127 | 56 |
| 08 MORE GALLERIES 판매작품 | 94 | 100 | 37 |
| 09 flower 연꽃사진 | 64 | 65 | 36 |
| 10 Exhibion View 장승 | 46 | 46 | 24 |
| 11 네팔 캄보디아 미얀마 | 98 | 105 | 82 |
| 12 風景 landscape | 56 | 66 | 77 |
| 13 도서발간 | 46 | 90 | 100 |

(저장 수가 API 작품 수보다 큰 것은 소개 섹션과 상세 페이지의 이미지가 더해졌기 때문이고, 작은 것은 같은 사진 중복 합침과 삭제된 원본 때문입니다.)

교훈은 세 가지입니다.
1. "전부 확보"는 사이트가 말하는 전체 수(`total`)와 맞춰 본 뒤에만 쓴다. 화면에 보이는 수와 맞춰 보면 안 된다.
2. 화면이 '더보기'나 무한 스크롤이면 첫 화면 HTML은 일부다. 페이지에 박힌 JSON의 `view`와 `total`부터 비교한다.
3. 결과 수가 다른 경로(페이지 이미지 vs 목록 데이터)와 어긋나면 먼저 구조를 의심한다.

## 4. 최종 결과
20개 메뉴, 이미지 1,443장, 약 1.29GB. 열림 검사 통과, 메뉴별 파일과 대응표 일치. 영상은 유튜브 9건(동영상 메뉴 8건 + 봉정사·통도사 메뉴 1건)의 주소만 기록했고 2건은 삭제·비공개로 조회되지 않았습니다. 받을 수 없던 것은 사이트 저장소에서 삭제된 원본 3장(11번 1장, 13번 2장)입니다. 게시판은 글 목록이 관리자 전용 공개라 수집할 글이 없었습니다. 해상도는 463~6720px로 메뉴마다 달랐습니다.

## 5. 이 저장소의 `scripts/collect.py`가 PC 버전(`history/v3_*`)에서 개선한 점
- 하드코딩 제거: 소유자 id, 계정 해시, 로고 해시, 메뉴 이름 목록을 홈 화면에서 자동 감지(`discover`).
- `--all`과 `--menu` 선택, `--lang ko|en` 폴더·파일 이름.
- 404(영구 실패)와 일시 오류를 구분: 404만 캐시하고 일시 오류는 다음 실행에서 재시도. 이전 버전은 모든 실패를 캐시했습니다.
- 파일 쓰기를 `.part` 임시 파일 후 교체로 바꿔 중간에 끊겨도 깨진 이미지가 남지 않음.
- 남은 파일을 `_이전파일`로 이동(삭제 권한이 없는 환경 대응).
- `status.json`, 종료 코드, 완료·미완료 표지 파일 분리(목록 API 실패 시 미완료로 표시).
- `verify` 통합: 열림 검사, 파일·대응표 일치, 목록 API 대조에서 내용 중복 흡수, 원본 삭제, 진짜 누락을 구분.
- `master`로 전체 대응표 생성.
- 메뉴 이름 목록(NAV) 하드코딩 대신 홈 링크 텍스트로 설명 글에서 메뉴 줄 제거.
- 단위 테스트 8개.

## 6. 미해결·한계
- 해상도: 사이트가 가진 최대 크기까지만 받을 수 있습니다. 인쇄용 고해상도는 작가에게 받아야 합니다.
- 삭제된 상세 페이지의 이미지가 목록에도 없으면 알 수 없습니다. 목록 API를 기준으로 완결을 판단합니다.
- 영상 파일은 받지 않습니다(저작권, 허용 도메인).
- Creatorlink 외 사이트에는 쓸 수 없습니다. 비슷한 애드블록 계열 빌더는 구조가 같을 수 있으나 확인하지 않았습니다.
- 이 도구의 영문 폴더 모드(`--lang en`)는 단위로는 확인했지만 장시간 실사용은 하지 않았습니다.
